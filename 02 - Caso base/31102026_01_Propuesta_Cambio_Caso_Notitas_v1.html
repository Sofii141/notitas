2La regla de diseño que mantiene válida la medición

Lo que se mide son tareas de lógica con pruebas automáticas. El front bonito se construye antes y no se mide.

Backend (lo que se mide)

  • Python + pytest, igual que ahora: cada tarea es una función con pruebas visibles y ocultas. Así siguen valiendo M1–M6, el sorteo y el script.
  • Un servidor sencillo (librería estándar o FastAPI) que guarda las notas en un JSON y responde: listar, crear, mover, filtrar y buscar.
  • Las reglas del tablero viven en las tareas t01–t24. El servidor solo las llama, como hace hoy la demo de CAMEIA-lite.

Front (lo que se ve, no se mide)

  • HTML, CSS y JS sin framework, con la paleta Macarons: columnas Por hacer · En curso · Hecho y notitas de colores ligeramente giradas.
  • Animaciones: arrastrar y soltar, la nota "se despega" al levantarla, rebota al soltarla, aparece con un pop y se archiva con un fade.
  • No valida nada: muestra lo que responde el backend. Si una tarea no está hecha, su función aparece "pendiente", así que la demo se va encendiendo a medida que avanzan.

Por qué no medir el front

Las animaciones no tienen un criterio de "terminado" objetivo ni pruebas ocultas, así que el cronómetro mediría gustos, no la práctica. Si lo construye la IA antes de medir, se declara: no es parte del experimento.
