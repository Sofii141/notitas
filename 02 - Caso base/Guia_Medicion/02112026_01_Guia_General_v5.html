1La idea en 30 segundos

Van a medir si programar con un agente de IA cambia las cosas frente a programar en pareja.

  • Línea base: ustedes dos en llamada, sin IA. Es lo que toca ahora.
  • Ciclos 1 y 2: cada uno solo con OpenCode. Es después.
  • Cada tarea es llenar una función de Python hasta que pasen sus pruebas, mientras anotan unos números en una ficha.

El recorrido siempre es el mismo

Guía (qué hacer) → Ficha (qué anotar en esa tarea) → Bitácora (Excel donde quedan los datos). Durante una tarea solo necesitan la ficha: trae los comandos. Si prefieren, me mandan los datos por el chat y yo lleno la bitácora y guardo la ficha.

3Palabras que van a ver

PalabraQué significa
Congelar el casoTomarle una "foto" al repositorio, con un nombre (un tag), para probar que después de ese momento nadie cambió las tareas ni las pruebas. No bloquea nada ni borra nada: pueden seguir programando normal.
Sorteo y semillaUn programa reparte las tareas. La semilla es el número que ustedes le dan: con el mismo número siempre sale lo mismo, y así cualquiera puede comprobarlo. Se corre una sola vez.
Conductor / naveganteConductor: quien escribe. Navegante: quien revisa, propone y detecta errores.
Pruebas visiblesSe pueden leer y correr todo el tiempo. Son solo una parte de lo que piden los criterios: pasarlas no prueba que se cumplan todos. Para terminar deben pasar todas y ustedes deben creer que ya cumplieron los criterios.
Pruebas ocultasSalen de los mismos criterios y revisan lo que las visibles no alcanzan a cubrir. No se abren antes. Se corren al terminar, y ese primer resultado cuenta cuántos errores se escaparon (M2).
RetrabajoEl tiempo corrigiendo lo que encontraron las ocultas, con otro cronómetro. Siempre se corrige hasta que pasen, sin límite de tiempo.
Codewalk5 preguntas, sin mirar el código, para ver si entienden lo que se programó.
S / M / LTamaño estimado de la tarea: pequeña, mediana o grande.

4Preparar todo (una sola vez, sin cronómetro)

Abran una terminal en la carpeta del código. Cada uno en su computador:

git pull
pip install pytest
python -m pytest -k t01

El último comando debe fallar con NotImplementedError: es lo correcto, porque la función aún está vacía.

Hojeen TAREAS.md solo para ver que se entiende, sin pensar soluciones. Luego, solo una persona congela y sortea (cambien 1234 por el número que quieran):

git tag congelado-notitas-v1
git push origin congelado-notitas-v1
python sorteo.py 1234 > registro/sorteo_1234.txt
git add registro/sorteo_1234.txt
git commit -m "Sorteo con semilla 1234"
git push

La otra persona corre git pull. Abran registro/sorteo_1234.txt: ahí están sus tareas. Anoten la semilla en la hoja Sesiones de la bitácora.

Si no alcanzan a hacer todas

Primero hagan la primera L, la primera M y la primera S que aparezcan en Orden para hacerlas. Después sigan ese orden. Las que no alcancen se dejan vacías y se explica en el análisis.

5Las grabaciones

Quien conduce graba su pantalla y el audio de la llamada (por ejemplo con OBS, o con la grabación de Meet o Zoom). El video es la evidencia de lo que pasó y permite revisar un tiempo si hay dudas, pero los minutos se toman con el cronómetro.

Guárdenlo en 99 - Videos/<etapa>/ con el nombre DDMMAAAA_S01_tNN_Conductor.mp4, y anótenlo en la ficha. No se sube a GitHub porque pesa: se comparte por Drive.

6Ver el tablero (opcional)

Lo importante son las pruebas: ellas dicen si una tarea está lista y de ellas salen los datos. El tablero es solo para ver cómo va quedando, al terminar una sesión y nunca con el cronómetro en marcha.

python backend/servidor.py

Abran http://localhost:8000. "Reglas encendidas: N/24" muestra cuántas funciones ya sirven. Para apagarlo: Ctrl + C en la terminal. Para volver a las notas de ejemplo, borren backend/datos.json.

  3. Completen la sección 12 (uso de IA) y envíen 02112026_01_Punto_Control_v5.pdf.
