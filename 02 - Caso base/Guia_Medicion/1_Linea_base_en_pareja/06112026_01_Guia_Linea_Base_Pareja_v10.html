1Cómo se trabaja

Los dos en llamada, sin IA, con VS Code Live Share. Uno conduce toda la tarea y el otro navega.

─── escribe el código  ·  - - - revisa  ·  · · · se consulta al agente  ·  decide quién acepta, corrige o rechaza

  • Conductor: escribe el código en su computador, comparte la carpeta con Live Share y explica en voz alta lo que hace.
  • Navegante: se une a la sesión de Live Share, sigue al conductor, revisa cada paso, piensa en casos borde y vigila los criterios. Puede señalar una línea, pero no edita.
  • Deciden los dos. Desactiven cualquier IA del editor (Copilot o autocompletado con IA).

Por qué 5: cubren los tres tamaños (2 S, 2 M y 1 L), que cambian el efecto del pair programming; quedan algo más que los 3 casos de cada escenario; y es un estudio exploratorio, que describe tendencias y no causas. Las dos que faltan son las siguientes del orden del sorteo, y prueban Live Share antes de los ciclos. El profe aceptó en la asesoría que la cantidad sea flexible si se justifica.

Las tareas de línea base que ya no se usan (t16, t04, t14, t20 y t10) pasan a E3 o a Repuestos/. Sus fichas de pareja quedan en Versiones anteriores/.

3Live Share, paso a paso

  1. Una vez: en VS Code, extensiones → Live Share (de Microsoft) → instalar, e iniciar sesión con GitHub o Microsoft.
  2. Quien conduce abre su repo en VS Code, empieza a grabar (OBS: pantalla y audio de la llamada) y da Live Share → Share. Manda el enlace por el chat.
  3. Quien navega abre el enlace, entra en modo Follow y sigue al conductor. Para señalar, selecciona la línea; no escribe.
  4. Al terminar, quien conduce da Stop collaboration session y para la grabación.

Live Share funciona, pero Microsoft ya no le agrega funciones. No graba sola: por eso se sigue grabando la pantalla. En la hoja Sesiones anoten "VS Code Live Share" en Herramientas.

4El ciclo de una tarea

  1. Abran su ficha en Plantillas/. Quien conduce graba y abre Live Share.
  2. Sigan la ficha de arriba abajo. Trae qué anotar y cada comando de git.
  3. Codewalk con el PDF de esa tarea en Codewalk/Por_tarea/.
  4. Guarden la ficha llena y las respuestas en Respuestas/tNN/, o mándenme los datos y las capturas del cronómetro.

Qué hace cada comando de git

git pull trae lo que subió el otro. git commit --allow-empty -m "t15: inicio" marca la hora en que empezaron: háganlo justo al arrancar el cronómetro. git add y git commit guardan su trabajo. git push lo sube.
