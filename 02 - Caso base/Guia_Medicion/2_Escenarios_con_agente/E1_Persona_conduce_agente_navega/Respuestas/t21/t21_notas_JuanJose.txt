from datetime import datetime, timezone

_IGNORADAS = {"modificado", "dispositivo"}


def _instante(valor):
    """Convierte una fecha ISO 8601 con zona a un datetime comparable, o None."""
    if not isinstance(valor, str):
        return None
    texto = valor.strip()
    if texto.endswith(("Z", "z")):
        texto = texto[:-1] + "+00:00"
    try:
        instante = datetime.fromisoformat(texto)
    except ValueError:
        return None
    if instante.tzinfo is None:
        instante = instante.replace(tzinfo=timezone.utc)
    return instante


def _dispositivo(version):
    return version.get("dispositivo") or ""


def _fecha(version, campo):
    modificado = version.get("modificado") or {}
    return _instante(modificado.get(campo))


def fusionar(base: dict, a: dict, b: dict) -> dict:
    """Ver TAREAS.md, tarea t21."""
    campos = (set(base) | set(a) | set(b)) - _IGNORADAS

    resultado = {}
    conflictos = []

    for campo in sorted(campos):
        valor_base = base.get(campo)
        valor_a = a.get(campo)
        valor_b = b.get(campo)

        if valor_a == valor_b:
            # CA2 (o ninguno cambió): ambos lados coinciden.
            elegido = valor_a
        elif valor_a == valor_base:
            # CA1: solo cambió b.
            elegido = valor_b
        elif valor_b == valor_base:
            # CA1: solo cambió a.
            elegido = valor_a
        else:
            # CA3: conflicto real.
            conflictos.append(campo)
            fecha_a = _fecha(a, campo)
            fecha_b = _fecha(b, campo)

            if fecha_a is not None and fecha_b is not None and fecha_a != fecha_b:
                elegido = valor_a if fecha_a > fecha_b else valor_b
            elif fecha_a is not None and fecha_b is None:
                elegido = valor_a
            elif fecha_b is not None and fecha_a is None:
                elegido = valor_b
            else:
                # Mismo instante (o sin fechas comparables): desempate alfabético.
                elegido = (
                    valor_a
                    if _dispositivo(a) <= _dispositivo(b)
                    else valor_b
                )

        if elegido is not None:
            resultado[campo] = elegido

    resultado["conflictos"] = sorted(conflictos)
    return resultado

Fecha sin zona horaria: si llegara una fecha naive, la trato como UTC (el enunciado promete zona, así que esto es solo para no romper).
Fecha ausente o inválida en "modificado" para un campo en conflicto: ese lado pierde frente a una fecha válida; si ninguno tiene fecha, se decide por nombre de dispositivo.
"dispositivo" ausente o None: se trata como cadena vacía, que quedaría primera en el orden alfabético.
Campo que falta = None se aplica literalmente: si a y b omiten un campo que existía en base, ambos "cambiaron a None" (CA2) y el campo desaparece del resultado.
"conflictos" se incluye siempre, incluso vacía, y también cuando el valor final del campo conflictivo es None (interpreto la frase "no se incluyen en el resultado" como referida a las claves de campos, no a la lista de CA4). Si prefieres que un conflicto resuelto a None tampoco aparezca en conflictos, basta mover el append después del filtro elegido is not None.
Orden alfabético = comparación de cadenas de Python (por punto de código, sensible a mayúsculas), igual que sorted(...) para los nombres de campo.
Nada de mutar los diccionarios de entrada: todo se construye en resultado.

"Buena pregunta: esa línea es la que define qué campos se van a fusionar, y las dos funciones resuelven problemas distintos.

set(): convertir las claves de un dict en un conjunto
Cuando le pasas un diccionario a set(), Python itera sobre él, y iterar un dict devuelve sus claves:

BASE = {"id": "1", "titulo": "Pan", "columna": "por_hacer"}
set(BASE)   # {"id", "titulo", "columna"}
Características de un conjunto que aquí nos sirven:

No hay duplicados: si id está en los tres diccionarios, aparece una sola vez.
No hay orden: no puedes indexar (conjunto[0]) ni confiar en el orden de iteración.
Operaciones de conjuntos: | (unión), - (diferencia), & (intersección).
Qué hace exactamente esa línea
campos = (set(base) | set(a) | set(b)) - _IGNORADAS
Se lee de izquierda a derecha, y los paréntesis mandan:

Paso	Expresión	Resultado (con el test visible)
1	set(base)	{"id", "titulo", "columna"}
2	set(a)	{"id", "titulo", "columna", "modificado", "dispositivo"}
3	set(base) | set(a) | set(b)	unión: todas las claves que existen en al menos una versión
4	... - _IGNORADAS	quita {"modificado", "dispositivo"}
5	resultado	{"id", "titulo", "columna"}
Es decir: la unión de claves de las tres versiones, menos los dos campos de metadatos.

Por qué unión y no las claves de base
Porque el enunciado dice que se fusionan todos los campos de base, a y b. Si un campo existe solo en a (campo nuevo creado en el celular) o solo en b, también hay que procesarlo. Si iteraras base.keys(), ese campo nuevo nunca se evaluaría.

Y al revés: si un campo está en base pero a y b lo omiten, sigue entrando en el bucle; dentro se lee con .get(campo), que devuelve None para las versiones donde falta — así se cumple "un campo que falta cuenta como None" sin necesidad de if campo in a.

Por qué - y no un if dentro del bucle
_IGNORADAS es un set justamente para poder restar. La alternativa equivalente sería:

for campo in campos:
    if campo in ("modificado", "dispositivo"):
        continue
    ...
Restarlo antes es más limpio: el bucle solo ve campos de datos y no arrastra la condición de filtrado en cada iteración.

Nota: set(base) | set(a) es lo mismo que set(base) | a (Python acepta cualquier iterable a la derecha), pero escribir set(...) en los tres lados es más explícito sobre la intención.

sorted(): recuperar un orden determinista
set no tiene orden, así que for campo in campos: iteraría en un orden arbitrario (estable dentro de una ejecución, pero no garantizado entre ejecuciones ni versiones de Python). sorted() toma cualquier iterable y devuelve una lista nueva ordenada:

sorted({"titulo", "columna", "id"})   # ["columna", "id", "titulo"]
Se usa en dos lugares con propósitos distintos:

for campo in sorted(campos) — no es estrictamente necesario para que las aserciones pasen (comparar dicts con == ignora el orden de las claves), pero:
hace la ejecución reproducible (mismo input → mismo orden de inserción en resultado),
al imprimir el resultado en un fallo de test se lee alfabéticamente, no en un orden aleatorio,
deja el código preparado si algún día se serializa el resultado.
resultado["conflictos"] = sorted(conflictos) — aquí sí es un requisito del enunciado: CA4 pide "la lista ordenada alfabéticamente de los campos que tuvieron conflicto". El bucle descubre los conflictos en el orden de iteración de campos, así que la lista hay que ordenarla explícitamente antes de devolverla.
Ojo con un detalle de sorted sobre cadenas: ordena por punto de código Unicode, no con reglas de diccionario. "Z" va antes que "a", y "Titulo" antes que "columna". Para los nombres de campo en snake_case (todo minúsculas, como en el proyecto) coincide con el orden alfabético esperado.

Resumen en una frase
set(...) | set(...) | set(...) - _IGNORADAS responde "¿qué campos hay que revisar?" (sin duplicados ni metadatos), y sorted(...) responde "¿en qué orden los recorro y en qué orden reporto los conflictos?" (determinista, y alfabético en el caso de conflictos, como exige CA4)."
