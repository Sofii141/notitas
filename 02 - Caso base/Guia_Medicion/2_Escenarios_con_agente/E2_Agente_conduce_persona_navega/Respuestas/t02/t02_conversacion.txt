## 1. Las piezas de arriba

```python
import re

HEX = re.compile(r"#?[0-9A-Fa-f]{6}")
```

- `import re` trae el módulo de expresiones regulares (patrones de texto).
- `re.compile(...)` **prepara** el patrón una sola vez y devuelve un objeto reutilizable. Es más limpio que recompilar el patrón en cada llamada.
- El patrón `#?[0-9A-Fa-f]{6}` se lee así:
  - `#?` → un `#`, opcional (`?` = cero o una vez).
  - `[0-9A-Fa-f]` → un carácter que sea dígito o letra hex, mayúscula o minúscula.
  - `{6}` → exactamente 6 de esos caracteres.

```python
PALETA = {
    "matcha": "#BCC86F",
    ...
}
```

Un **diccionario**: relaciona cada nombre con su hex canónico. Sirve para dos cosas: buscar por nombre (`PALETA[nombre]`) y obtener la lista de hex válidos (`PALETA.values()`).

## 2. La función, línea por línea

```python
def normalizar_color(c: str) -> str:
```
Recibe un texto y promete devolver otro texto (el hex canónico). Si algo no cuadra, lanza `ValueError`.

```python
    texto = c.strip()
```
`strip()` quita espacios (y saltos de línea/tabs) **solo de los extremos**: `"  Matcha "` → `"Matcha"`. Los espacios internos se quedan, así que `"mat cha"` sigue siendo inválido.

```python
    nombre = texto.lower()
    if nombre in PALETA:
        return PALETA[nombre]
```
`lower()` pasa todo a minúsculas para comparar sin importar mayúsculas. Como las claves del diccionario están en minúsculas, `"MATCHA"` y `"Matcha"` caen en la misma clave. Si existe, devuelvo directamente el valor del diccionario, que **ya está en formato canónico** (`#` + mayúsculas).

```python
    if HEX.fullmatch(texto):
```
Aquí está el detalle importante: uso `fullmatch`, no `match` ni `search`.
- `fullmatch` exige que **todo** el texto encaje con el patrón.
- `match` solo exige que encaje **al principio**, así que `"BCC86F0"` pasaría (los 6 primeros caracteres) y luego daría un resultado incorrecto.
- `search` buscaría el patrón en cualquier parte, peor aún.

Con `fullmatch`, `"#BCC86F0"`, `"#BCC86"`, `"0x123456"` o `"hola BCC86F"` no pasan.

```python
        hex_canonico = "#" + texto.lstrip("#").upper()
```
- `lstrip("#")` quita el `#` **solo del inicio** (a diferencia de `strip`, que quitaría de ambos lados, y de `replace`, que quitaría todos). Quito el `#` para no duplicarlo al añadir el mío.
- `.upper()` pone los dígitos hex en mayúsculas.
- `"#" + ...` arma el formato canónico de CA2: `#` + 6 dígitos en mayúsculas.

```python
        if hex_canonico in PALETA.values():
            return hex_canonico
```
Esta es la parte que hace cumplir CA3. El patrón solo dice "esto *parece* un hex"; aquí verifico que sea **un color de la paleta**. `PALETA.values()` devuelve los seis hex permitidos, así que `#123456` es hex válido pero no está en la lista → no se devuelve. Así no repito la lista de colores en dos sitios.

```python
    raise ValueError(f"Color no válido: {c!r}")
```
Si nada de lo anterior devolvió, es que el valor no sirve. `raise` lanza la excepción y corta la función. El `!r` del f-string usa `repr()`, que muestra el valor entre comillas y hace visibles los casos raros: `Color no válido: ''` en vez de un mensaje vacío.

## 3. Cómo se comporta con ejemplos

| Entrada | `texto` | ¿nombre? | ¿hex válido? | Resultado |
|---|---|---|---|---|
| `"  Matcha "` | `Matcha` | sí (`matcha`) | — | `#BCC86F` |
| `"bcc86f"` | `bcc86f` | no | sí | `#BCC86F` |
| `"#f5cb99"` | `#f5cb99` | no | sí | `#F5CB99` |
| `"#123456"` | `#123456` | no | hex sí, paleta no | `ValueError` |
| `"verde"` | `verde` | no | no | `ValueError` |
| `""` | `""` | no | no (faltan 6) | `ValueError` |

## 4. Por qué el orden es este

Primero nombre, luego hex. No es obligatorio (no hay solapamiento entre nombres y hex), pero deja el caso más común arriba y hace el flujo fácil de leer.

Un detalle: `PALETA.values()` es una "vista" del diccionario y el `in` recorre los 6 valores; con 6 elementos es irrelevante. Si la paleta creciera mucho, se podría tener un `set` de hex permitidos y consultarlo en O(1), pero sería una optimización innecesaria aquí.
